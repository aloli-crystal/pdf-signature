== v0.1.3 — 2026-06-04 — PAdES B-B fonctionnel

=== Added

* **`Signer.sign_with_options` — orchestration PAdES B-B complète.** Le
  PDF d'entrée est signé par un **incremental update** : les octets
  d'origine restent intacts et l'on ajoute, en fin de fichier, le dict
  /Sig (placeholders /Contents + /ByteRange), le champ de signature
  (widget /FT /Sig invisible), l'AcroForm (/SigFlags 3), les versions
  mises à jour de la page (/Annots) et du catalog (/AcroForm), une table
  xref incrémentale et un trailer /Prev. Le /ByteRange réel et le
  /Contents (PKCS#7 hex) sont ensuite patchés in-place.
* `ByteRange.compute` distingue désormais le /Contents **hexadécimal de
  la signature** du /Contents de la page (référence vers le flux) — il
  retient le `/Contents` suivi d'un `<` dont le `>` tombe exactement à
  la taille réservée.
* Placeholder /ByteRange élargi à 4 entiers de 10 chiffres
  (`BYTE_RANGE_PLACEHOLDER`) pour un patch in-place sans décalage.

=== Validation

PDF signé **validé par deux outils tiers** : `openssl cms -verify`
(round-trip dans les specs) et **`pdfsig` (poppler)** sur un vrai
fichier → « Signature Validation: Signature is Valid », « Total document
signed », type adbe.pkcs7.detached, SHA-256. Le certificat auto-signé
ressort « issuer isn't Trusted » (attendu, hors chaîne de confiance).

=== Changed

* Dépendance `pdf` relevée de `~> 0.5` à `~> 1.0` (1.6.0) pour disposer
  d'AcroForm / champ de signature et du writer xref-stream.

== v0.1.2 — 2026-06-04

=== Added

* **`PKCS7.sign` / `PKCS7.verify`** — the cryptographic core of PAdES
  B-B, implemented via the `openssl` CLI (the design choice of
  `doc/RATIONALE.adoc`). `sign` extracts the leaf certificate and
  private key from the PKCS#12 (passphrase passed through an
  environment variable, never on the command line ; PEM material in a
  0700 temp directory removed in an `ensure`) and produces a **detached**
  CMS SignedData (`openssl cms -sign -binary -outform DER -nosmimecap
  -md <digest>`). `verify` checks a detached signature against supplied
  content, optionally against a CA bundle.
* Specs : a round-trip (sign then verify) with an on-the-fly
  self-signed PKCS#12, a detached-envelope check (the signed content is
  not embedded in the DER), tamper rejection, and a missing-PKCS#12
  error. The signing dance (`/Sig` insertion, `/ByteRange`, `/Contents`
  patching) lands in the next 0.1.x.

== v0.1.1 — 2026-05-07

=== Fixed

* **`PDF::Signature::VERSION` read at compile-time from `shard.yml`**
  (instead of being hardcoded). Pattern reproduced identically in
  `aloli-crystal/pdf` v0.5.4 and `aloli-crystal/crystal-combine-pdf`
  v1.0.31.34. Bug consumers would see: the Crystal constant and the
  `shard.yml` `version:` could silently diverge because the manual
  release bump might forget one or the other. The `read_file` macro
  removes that risk.

* `pdf_signature_spec.cr` updated: now compares `PDF::Signature::VERSION`
  to the parsed `version:` from `shard.yml` at runtime.

== v0.1.0 — 2026-05-07

**Shard creation and initial skeleton.** The shard is set up,
foundations are written, PAdES B-B implementation will land in
a subsequent 0.1.x release.

=== Added

* `doc/RATIONALE.adoc` (in French) — consolidated reference
  document covering digital signature principles, the 4 PAdES
  levels (B-B / B-T / B-LT / B-LTA), TSA construction (internal,
  public, eIDAS qualified), the Sigstore model and its potential
  application to French-speaking Crystal community, and the
  sequenced ALOLI trajectory toward a trust infrastructure.

* Crystal shard skeleton: `shard.yml`, `README.{adoc,fr.adoc}`,
  `CHANGELOG.{adoc,fr.adoc}`, `LICENSE` (MIT), `.gitignore`,
  `.editorconfig`.

* `PDF::Signature` module with its version and a `Signer.sign`
  entry-point (stub) that raises `NotImplementedError` until the
  B-B implementation ships.

* Minimal spec suite that passes (at least the version).

* Dependency on `aloli-crystal/pdf` ≥ 0.5 (PDF object model,
  parser, writer).
